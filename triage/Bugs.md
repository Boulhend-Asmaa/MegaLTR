# MegaLTR Bug Tracker

This file contains all issues found while running MegaLTR as is.
(before any refactoring or Nextflow migration).

---

## Run r01 – Initial run (as-is)

### BUG-001 – Example script does not work
- **File:** MegaLTR_Run_Example.sh
- **Problem:** Script does not pass required arguments (-A, -F)
- **Evidence:** 
  Parameters -A and -F is required
- **Impact:** Example provided in the repository fails immediately
- **Status:** Not fixed

---

### BUG-002 – Missing Perl dependency (Bio::SeqIO)
- **File:** bin/RUN/checkfasta.pl (line 4)
- **Problem:** Bio::SeqIO module not found
- **Evidence:**
  Can't locate Bio/SeqIO.pm in @INC
- **Impact:** Pipeline stops at FASTA validation step
- **Status:** In progress (dependency resolution)

---

### BUG-003 – GenomeTools suffixerator fails
- **Tool:** gt suffixerator
- **Problem:** Cannot detect FASTA file type
- **Evidence:**
  gt suffixerator: error: cannot guess file type of file test_run.fna
- **Impact:** Downstream steps (ltrdigest) fail due to missing index
- **Likely cause:** Invalid or empty FASTA generated by previous step
- **Status:** Not fixed
### BUG-004 – Legacy Perl FASTA check using BioPerl
- **File:** bin/RUN/checkfasta.pl
- **Problem:** Script only validates FASTA format but depends on BioPerl
- **Evidence:** use Bio::SeqIO causes runtime failure
- **Impact:** Pipeline stops early due to unnecessary heavy dependency
- **Suggested fix:** Replace with lightweight Python FASTA validator

### PERF-001 – Inefficient GenomeTools (gt) discovery
- **Location:** MegaLTR.sh (LTR_HARVEST section)
- **Problem:** Script calls `conda config --show envs_dirs` then loops through all env dirs using `less` to locate `gt`.
- **Impact:** Slow, fragile, and may trigger redundant attempts; depends on filesystem layout.
- **Suggested fix:** Use `GT_BIN=$(command -v gt)` or `GT_BIN=$CONDA_PREFIX/bin/gt` and run LTR_HARVEST once.

### BUG-005 – Misleading comment: “copy and split fasta”
- **Location:** MegaLTR.sh
- **Observation:** Comment indicates FASTA splitting but shown code only performs header cleanup and tool execution on full FASTA.
- **Impact:** Documentation mismatch; unclear workflow; harder to port to Nextflow.
- **Action:** Search for actual splitting logic elsewhere or update comment.

### RISK-001 – In-place FASTA header editing
- **Location:** MegaLTR.sh (sed -i on `$process_id.fna`)
- **Problem:** Modifies FASTA directly, no backup.
- **Impact:** Harder debugging; potential downstream inconsistencies.
- **Suggested fix:** Write cleaned FASTA to a new file and keep original intact.
