## Known Limitation Requiring Discussion

During implementation, I encountered a technical limitation with the gt ltrdigest tool from GenomeTools:

**Issue:** The tool has hard-coded GFF3 format requirements that are incompatible with LTR_retriever's output format (expects "seqX" sequence IDs but receives actual chromosome names like "RGr4HXLh0o").

**Impact:**
- Core workflow (8/19 processes) is fully functional
- 11 downstream processes (MERGE_RESULTS through RESTORE_IDS) are blocked as they require LTRDIGEST's protein domain annotations
- Missing analyses: domain annotations, insertion time estimation, and gene interaction analysis

**Investigation Conducted:**
- 10 commits attempting various solutions
- Fixed file staging issues and GFF3 attribute problems
- Identified root cause: sequence ID format incompatibility in GenomeTools source code

**Resolution Options Identified:**
1. Implement ID translation layer (1-2 weeks development)
2. Modify GenomeTools source code (requires external contribution)
3. Find alternative domain annotation tool (3-6 weeks evaluation)
4. Refactor merge scripts for TEsorter-only mode (2-3 weeks)
5. Document as future enhancement

All options are detailed in PHASE6_COMPLETION_SUMMARY.md with effort estimates and trade-offs.
